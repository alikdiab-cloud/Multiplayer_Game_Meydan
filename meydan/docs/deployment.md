# Deployment

The Render Blueprint, Dockerfile, and `.dockerignore` in this workspace are configured for a repository whose root is the parent workspace: the directory containing `meydan/`. The Docker context is that repository root, and the Dockerfile copies application files from `meydan/`. The ignore file keeps the parent README, parent docs, local caches, credentials, dependency trees, generated output, test artifacts, and archives out of the context.

## Repository root choices

- **Publishing the parent workspace:** keep `render.yaml`, `Dockerfile`, and `.dockerignore` at the parent root. Render uses `dockerContext: .` and `dockerfilePath: ./Dockerfile`; the Dockerfile's `COPY meydan/...` paths are relative to this context. Do not set Render's `rootDir` to `meydan`, because the image build context must include the parent root and its `meydan/` directory.
- **Publishing `meydan/` alone:** the parent-level deployment files are outside that repository and will not be available to Render. Put the deployment files at the new repository root, change Dockerfile copies from `meydan/package.json`, `meydan/package-lock.json`, and `meydan/` to `package.json`, `package-lock.json`, and `.` respectively, and adjust/remove parent-only `.dockerignore` entries. Use `dockerContext: .` and `dockerfilePath: ./Dockerfile`; omit `rootDir` because the repository root is already the app root.

Render builds the compiled client and server with `npm run build`, then runs `node dist/server/production.js`. `npm ci` uses the committed lockfile in both build stages; the final image contains only production dependencies, the compiled output, and the package metadata needed for ESM. The runtime uses Node 24 as the unprivileged `node` user. Render's `PORT` environment variable is not overridden by the Blueprint; the container's `10000` default is for local Docker runs. The server binds `0.0.0.0`, and both HTTP and Socket.IO share that port. Render's web service proxy supports WebSocket upgrades; see [Render WebSockets](https://render.com/docs/websocket) and [Render web services](https://render.com/docs/web-services).

The Blueprint configures one free instance and uses `/api/health` for its health check. Free Render web services can sleep after 15 minutes without incoming HTTP requests or WebSocket messages; waking can take about a minute. Render may restart them, their filesystem is ephemeral, and the free plan has monthly usage limits. This app keeps rooms and sessions in process memory, so sleeping, restarts, and deploys end active rooms. Free hosting is suitable for trying the service, not uninterrupted games. Keep this deployment at one instance: the in-memory room and session registries are not shared across instances. See [Render's free service limits](https://render.com/docs/free) and [health check behavior](https://render.com/docs/health-checks).

## Public origin behind a proxy

The server reads `PUBLIC_ORIGIN` only to compare the `Origin` header on Socket.IO handshakes with the browser-visible public origin. Without it, the server derives an origin from the request's `Host` header and whether the connection reaching Node is encrypted. A proxy that terminates HTTPS or rewrites the host can make that derived origin differ from the browser's `Origin`.

Set `PUBLIC_ORIGIN` to the one exact public HTTP(S) origin, such as `https://meydan.example.com` or `https://meydan-1234.onrender.com`. Use the actual hostname assigned to the service. Do not include a path (including `/socket.io`), query, fragment, username, or password. Keep the proxy's forwarded `Origin` unchanged and forward WebSocket upgrades for `/socket.io` to this same server instance. This value does not configure the proxy, change the client URL, or provide state sharing. The app rejects malformed values and handshakes whose supplied `Origin` differs from the configured origin; requests without an `Origin` header remain permitted by the current server defaults.

The Render Blueprint prompts for `PUBLIC_ORIGIN` because the actual public hostname is assigned by Render or selected as a custom domain. If that hostname is not known during initial Blueprint setup, set the environment variable in the service settings once it is known. Render terminates public TLS and forwards requests to the service over HTTP, so set the public `https://` origin for browser Socket.IO connections. Render's [Blueprint reference](https://render.com/docs/blueprint-spec) documents the Docker context, health check, and `sync: false` environment variable fields.
